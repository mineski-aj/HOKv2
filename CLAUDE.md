# HOK (v2) — instruction manual

HOK esports broadcast overlay server. Each overlay is a browser-source page (OBS/vMix) fed by the live HOK match API and controlled from one dashboard. Read this before touching anything.

## Running it

`node server.js` (or `npm start`, or `run.bat` on Windows), port **7788** (`PORT` in `.env`). Dashboard `/dashboard`.

**`lib/*.js` and `routes/*.js` are not hot-reloaded — restart required.** `html/**` changes apply on the next page load. The server is usually the operator's own terminal process: say so and ask before restarting.

`.env` (optional): `PORT`, `FETCH_INTERVAL_MS` (API poll, default 1000), `DATA_DIR`, `ASSETS_DIR`.

**Layout:** this folder (`HOK/`) IS the v2 app — the old v1 app and the nested `HOKv2/` folder were removed 2026-11-17 (v1 is still in git history). **Assets** are served at `/assets` from `./assets` (~1 GB; `ASSETS_DIR` in `.env` overrides). Hero art lives in `assets/hero/` (`full/` `<id>_FHD.png`, `draftpick/` `<id>_TINGGI.png`, `square/` `<id>_KOTAK.png`, `webm/` `<id>.webm`). `0000 HOK API/` = the provider's API docs + credentials (not used by the code).

### Adding a new show/hide panel (checkOverlays pattern) — every miss is silent
1. `lib/state.js`: add the key to `checkOverlays` (routes are generated from this object). Default `true` if normally on.
2. `html/js/overlay-shared-worker.js`: add the key to `KNOWN_EVENTS` **and bump `OVERLAY_WORKER_VERSION`** in `overlay-sse-shim.js` (open pages keep the old worker otherwise).
3. Page: restore from `/overlay/check-overlays`, `sse.addEventListener('<key>', …)`, and a `previewTrigger` branch. If normally on, default CSS to the SHOWN state and add a hidden class (no blank flash during restore).
4. `dashboard.html`: add `{ name, key, previewButton: true }` to the overlay's `checkToggles`, and the key to the `dashboardSSE` listener list (else the button drifts out of sync).
5. Verify in a real browser: click the real Control toggle and confirm a *separate* tab reacts; `curl` only proves the route exists.

New armable feature: add to `featureToggles` in `lib/state.js`, `HokFeatures` in the page, `featureToggles` in the dashboard entry.

## In-Game Overlay — QUADRANTS (overlay.html)

- The frame is split into four quadrants: **top, bottom, left, right**. Panels in DIFFERENT quadrants can be live together; panels in the SAME quadrant replace each other — the one that's up animates OUT, and only then does the new one animate IN.
- Page: `js/overlay-quadrants.js` (`HokQuadrants.register(key, quadrant, el, { outMs, onShow })`, `set/show/hide`). Show = `.show` on the panel element; each panel's CSS owns its own in/out transition and `outMs` must equal its out-transition length. `onShow` may return a Promise (data fetch) the panel waits for (max 800 ms) so it never slides in empty. Same rule in preview (`previewTrigger`). Dashboard ◈ Preview buttons are exclusive per `previewGroup` (checkToggles field; default = one at a time): Top Bar `q-top`, Item Check `q-bottom`, Damage Rank / Gold Rank `q-right`, Test Background `testbg` — so panels in different quadrants preview together, and a same-quadrant preview hands over without sending a hide (the page animates the old one out).
- Server: `INGAME_QUADRANTS` in routes/overlay.js (`{ topbar: 'top', itemcheck: 'bottom', damagerank: 'right', goldrank: 'right' }`) — `showCheck` hides the other panels of that quadrant first. Keep it in sync with the `register` calls in overlay.html.
- Current panels: Top Bar → top, Item Check → bottom, Damage Rank + Gold Rank → right (they replace each other). Left is free. Kill/objective events are NOT quadrant panels (full-frame event layer, z-index 50, on top of everything).
- **Adding a panel**: checkOverlays key (lib/state.js) + `INGAME_QUADRANTS` + `KNOWN_EVENTS`/worker version + markup/CSS with a `.show` transition + `HokQuadrants.register` + add it to `QUAD_KEYS` in overlay.html + dashboard `checkToggles`/`dotKey`/dashboardSSE list + an Edit config.

## Post Hexagon (fullscreen.html)

- **Matchup (role) change on air** (`setRole`): every swappable element is diffed against its `data-sig` (hero art, photo, role icon, name, hero name, each item slot, each stat label/value); identical content is not touched. New images are decoded first. Then: **player photos + the two radar shapes fade OUT (240 ms) and back IN**; everything else that changed **CROSSFADES** old → new with no gap — `makeGhost()` lays a frozen copy of the old element exactly over it (same offset parent/offsets/size + computed text/image styles), the real element swaps content at opacity 0, then ghost fades out while the element fades in (360 ms); ghosts removed at 450 ms. Radar grid, plates, "HERO USED", panel and the shared header/match info never move. ## Fullscreen scenes — seamless switching (keep this way)

- Scenes are **mutually exclusive** server-side (`FULLSCREEN_SCENES` in routes/overlay.js): showing one broadcasts `hide` for the others first.
- **Shared layer** (`#fs-bg-video`, `#fs-header` = VICTORY/DEFEAT, logos, team codes, series scores, event logo, year; `#fs-ticker`) is NOT inside any scene. Each scene's `show()` calls `FsShared.claim(name)` immediately and `FsShared.reveal(name, data)` when ready; `hide()` calls `FsShared.release(name)`. The layer fades only if nothing re-claims it within 300 ms, so on a switch only the scenes' own elements cross-fade — the video never restarts or dips (verified by sampling).
- Shared GAME TIME | GAME n block (`#fs-gameinfo`): only shown while the visible scene claimed it with `{ gameInfo: true }` (Post Stats, Post Gold Graph). Shared MATCH n / series block (`#fs-matchinfo`): `{ matchInfo: true }` (Post Hexagon, Post Items). Each stays perfectly still when switching between two scenes that both use it.
- A NEW scene must: live in its own `.fs-scene` container, NOT duplicate header elements (use `#fs-*`), call claim/reveal/release, be added to `FULLSCREEN_SCENES`, `SCENES` in fullscreen.html, `KNOWN_EVENTS` (+ bump worker version), dashboard `checkToggles` / `dotKey` / dashboardSSE key list, and get an Edit config built as `FS_SHARED_ELEMENTS.concat(<SCENE>_ELEMENTS)` (shared selectors → moving the header in one config moves it in all).

## Post Gold Graph (fullscreen.html)

- **The HOK API has no gold history** (only current team gold), so `lib/goldTimeline.js` RECORDS it: `lib/poller.js` calls `goldTimeline.record(battleId, teams)` every tick → one `[t, camp1Gold, camp2Gold]` sample per game second in `data/gold_timeline.json` (written every 5 s, new battle = fresh timeline, cleared by Clear Match). ## Data flow

- Control (show/hide/arm/test) = SSE push. Data (scores, draft, players) = each page's single `HokPoll` loop every 500 ms (`state`, `ingame`, `teams`, `draft` sources). Don't add per-module `setInterval` fetches — `HokPoll.register(fn)`.
- Saving config (`POST /api/state`) broadcasts `appstate`: pages poll immediately, other dashboards re-sync.
- Camp 1 = Team 1 = home/left; camp 2 = away/right. The Top Bar auto-corrects sides from the majority nickname prefix per camp.
- Kill/objective detection: first poll of a battle (and every poll while disarmed) only records a baseline — nothing old fires. One shared queue, 4 s per event (box in at 1.0 s, out at 3.3 s).
- Companion auto-trigger runs **in the dashboard** (LED & Companion tab) while it is open: kills from player stats, objectives from team stats, FIRST PICK = AWAY flips camp 1 onto the away paths, max one press per 1.5 s.

## Preview — isolated from the broadcast

Control-tab pages load with `?preview=1` (`HOK_PREVIEW`): they ignore real show/hide SSE and the restore fetch, never auto-fire events, never play hero voice lines, and are driven only by `window.previewTrigger(event, action)`. The dashboard's ◈ buttons call that (one active at a time). Nothing in a preview may call the server's control routes.

## Edit tab

`overlay_styles.json` = `{ [styleFile]: { [selector]: { left, top, width, height, fontSize, display } } }` (`overlay`, `draftpick`, `draftled`). Pages inject them as `!important` rules; Save broadcasts `reload`.

**Every element needs its own id + absolute position in canvas coordinates**, and the SAME selector in three places: the page CSS/DOM, `*_DEFAULTS`, and `*_ELEMENTS` in `dashboard.html`; then an `EDIT_CONFIGS` entry (`editCss` forces the scene visible, `call` puts sample content up, `size` for non-1920x1080). Defaults must equal the CSS values. Font sizes are px.
